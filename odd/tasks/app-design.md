# Feature: app-design

Objective: update the Figma style guide (file `uMjLWyytKzdU4AgXuNBRZM`, page `Style Guidelines`) to the current visual language mapped to Material 3, finish what the old guide left undone, and design wireframes and mockups for the new Kotlin (Android) app.
Branch: `feat/app-design` from `develop`. Delivery: ask-on-risk; repo changes are this document only. Tests: no runner applies (Figma work); each task is checked with Figma screenshots and structural readback.

## Specs

- S1 "hay que actualizarla y aprovechar para desarrolar lo que no se hizo hasta el momento." Update the old Figma style guide and complete the missing parts.
- S2 Base visual language (user choice, 2026-10-23): "Código actual + M3" — take the language already in code (`src/styles/tokens.css`, `docs/visual-language.md`: Fraunces, Inter, brand green as fill, forest ink, lavender accent, large soft radii, flat soft shadows) and map it to Material 3 color roles and type scale so it translates directly to a Jetpack Compose theme. The old guide is archived, not deleted.
- S3 "la parte del prototipo sera ahora una app hecha en kotlin" — target platform is Android (Kotlin). Assumption: Jetpack Compose + Material 3, phone first.
- S4 "desarrollaremos los wireframes y mockups en el figma" — wireframes and mockups live in the same Figma file.
- S5 Screen scope (user choice, 2026-10-23): "Paridad con la web" — the 12 areas of the web prototype: auth, búsqueda, inicio, detalle, publicar, dashboard, comunidad, notificaciones, gamificación, perfil, ajustes, chat.
- S6 UI copy in Spanish (as in the web app); layer and component names in English.
- S7 Wireframe fidelity and style (user, 2026-10-23): "los wireframes tienen mucho detalle para mi gusto. me gustaia ver mas inspiracion del ultio material ui design language." Wireframes drop to low fidelity (blocks and text bars, real copy only for titles and actions) and take their structure from Material 3 Expressive (varied shapes, larger emphasized headlines, button groups, split button, FAB menu, floating toolbar, flexible navigation bar, loading indicator, wavy progress).
- S8 Coverage (user, 2026-10-23): "no se mapean todas las pantallas, por ejemplo en el onboarding no se muestran todos los estados". Every flow shows all its screens and states (empty, loading, error, success, permissions, system dialogs), listed in a screen and state map.
- S9 Report findings (user, 2026-10-23): "considera solo los puntos 1 y 2" — from the original report (`docs/upc-pre-202502-si385-4178-ReflowTech-report-tf1.docx`) take only (1) the missing features: trade lifecycle (proposal, reserved listing, safe meetup, QR close with fallback code and offline sync, rating after close, impact receipt, object timeline, "Mis intercambios"), two-level verification (Básica phone, Avanzada DNI + selfie, "Raíz Verificada"), reports and moderation (reasons, case ID, states), my listings states (Activo, Reservado, Pausado; reserved cannot be deleted), points store states (insufficient, sold out, waitlist), versioned terms with re-accept, low-data mode, TalkBack, languages ES / Quechua / EN; and (2) the validation findings: labeled bottom-nav icons, "trueque" explicit in onboarding, short publish form (photo, title, category first, then "agregar más detalles"), prominent verified badge on the avatar with text, OTP attempt limit + resend timer + "Contáctanos". Out of scope: the report's non-functional requirements and its old style guide.
- S10 Navigation (user, 2026-10-23): "va" to "Intercambios reemplace a Chat como pestaña en la barra inferior y que el chat viva dentro de cada intercambio". Bottom bar: Inicio, Buscar, Intercambios, Comunidad, Perfil; Publicar = FAB; chat opens from a trade (and from Detalle via the proposal). Supersedes the Chat tab in L7.
- S11 Viora ideas (user, 2026-10-23): "va" to "sumar a la guía de Mink'a la sección de tono de comunicación y los controles de selección". Add a communication-tone section to Foundations (tone sliders, tagline, voice rules from the report: clear, no jargon, gender-inclusive, 1–2 emojis max only in playful contexts, do/don't microcopy) and selection controls (checkbox, radio, switch with enabled/disabled states) to the Library, bound to variables like the other components.
